# 字幕节奏修复 Web 应用（Subtitle Rhythm Fixer）

在浏览器中导入 SRT 字幕，选取**至多 30 条连续字幕**，设置**每秒字符数（CPS）**、
**单行字数**与**最小提示间隔**。应用在

- **文字内容与顺序不变**
- **片段总起止时间不变**（首条起点、末条终点固定）

的前提下，**联合调整断句（换行位置）与毫秒边界**，求出满足全部限制且
**总边界移动量（Σ|新边界−原边界|）最小**的方案；若无解，则逐条列出冲突规则。
结果与原稿**并排展示**并高亮移动的文字与时间，确认后导出修复后的 SRT。
所有数据仅保存在**本浏览器（localStorage）**，不上传任何服务器。

## 一条命令启动

需要 Docker（含 Compose 插件）：

```bash
docker compose up -d --build
```

启动后打开：

> **http://localhost:8080**

停止：

```bash
docker compose down
```

## 配置（端口）

默认宿主机端口 **8080**，容器内为 80。更换端口有两种方式：

```bash
# 方式一：环境变量
APP_PORT=9000 docker compose up -d --build

# 方式二：直接改 docker-compose.yml 中 "${APP_PORT:-8080}:80" 左侧端口
```

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 宿主机端口 | `8080` | 浏览器访问端口，可用 `APP_PORT` 覆盖 |
| 容器端口 | `80` | Nginx 监听端口，一般无需改动 |
| 数据存储 | 浏览器 localStorage | 键名 `subtitle-rhythm-fixer:v1`，可在页面中“清空数据” |

## 本地开发（不用 Docker）

需要 Node.js 20+：

```bash
npm install
npm run dev        # 开发服务器，默认 http://localhost:5173
```

开发端口可用环境变量更改：`PORT=9000 npm run dev`。

生产构建与本地预览：

```bash
npm run build      # 类型检查 + 产出 dist/
npm run preview    # 预览构建产物，默认 http://localhost:4173
npm run test:solver # 运行求解器算法测试（约束满足、最优性、无解诊断）
```

## 使用流程

1. **导入 SRT**：点击选择或拖拽 `.srt` 文件（兼容序号缺失、`.` 毫秒分隔等变体）。
2. **选择片段**：下拉框选择起点/终点，或点击表格行设起点、Shift+点击设终点；
   单次最多 30 条连续字幕。
3. **设置参数**：
   - **每秒字符数 CPS**：每条字幕时长必须 ≥ 字数 ÷ CPS；
   - **单行字数**：重新断行后每行不超过该字数（中文按字、拉丁文按词，超长词才截开）；
   - **最小提示间隔（ms）**：相邻字幕之间“上一条结束 → 下一条开始”的最小空隙。
4. **计算最优方案**：
   - 有解：显示总边界移动量等统计，并在右侧给出修复结果；
   - 无解：列出所有冲突规则（哪些条目 CPS 时长不足、间隔缺口、超出片段跨度多少）与调整建议。
5. **并排核对**：黄色高亮跨行移动的文字；绿/红徽章标出每条开始/结束边界的毫秒位移；
   `↵` 表示换行位置。
6. **确认并导出**：点击“确认应用修复”写回所选字幕，再“导出 SRT”下载
   `*.fixed.srt`（未选中字幕原样保留，全片序号重新连续编号）。

## 算法说明

设选中 n 条字幕的边界变量为 `x = [s1,e1,s2,e2,…,sn,en]`（共 2n 个），片段固定
`x0 = S`、`x_{2n−1} = E`。相邻变量最小间隔：

- `e_i − s_i ≥ ⌈字数_i × 1000 / CPS⌉`
- `s_{i+1} − e_i ≥ 最小间隔`

用累积下界把所有差分约束化为 `u` 的单调不减约束，目标变为**固定端点的 L1 等距回归**，
以加权 **PAVA（Pool Adjacent Violators Algorithm）取加权中位数**求解，得到全局最优的
最小总边界移动量。可行性等价于“约束最小总跨度 ≤ 片段可用跨度”；无解时给出精确到
毫秒的缺口诊断。所有时间均为整数毫秒，最优解自然为整数。

字符数按 Unicode 码点计，行间折叠的空格也计入（与 CPS 口径一致）。

## 技术栈

React 18 + TypeScript + Vite；构建产物由 Nginx 静态托管（多阶段 Docker 构建）。
